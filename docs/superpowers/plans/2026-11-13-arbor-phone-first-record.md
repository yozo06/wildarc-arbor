# Phone-first Arbor: build record

What happened while the [plan](2026-11-13-arbor-phone-first.md) was built, on 2026-11-13: the decisions taken
along the way, the review, and what is left. The branch is `feature/arbor-phone-first`, on top of
`feature/arbor-land-map`.

## Pull requests

The branch can go up as one pull request (after the CI repair and the Land Map), or as one per design step. To
split it, cut a branch at the last commit of each step:

## Results

- Frontend: type check clean; 150 tests pass under Node 26; the phone build and the server build succeed.
- Backend: 16 of 17. The one failure is the schema test that `fix/ci-schema-test-and-cookie-ignore` repairs.
- Checked in Chrome at phone size: adding trees, health and work entries; the sample farm; the Land Map; a farm
  file saved and opened through real IndexedDB (with a photo, byte for byte); a 3000 by 2000 image stored as a
  1600 px JPEG; the Pages build under `/wildarc-arbor/` with its service worker active.
- A fresh clone runs the phone version with `npm ci` and `npm run dev` in `frontend/`, nothing else.

## Decisions taken while building

Each was the smallest change that kept to the design; none changes what the owner approved.

- Phone records keep the numeric ids the screens compare, plus a `uid` for a later sync.
- The status list includes `on_hold`, which the tree screens offer.
- The phone version's sign-in state is saved under its own key, so a server session on the same address cannot
  leak a server role into it.
- Photos are stored as bytes with their type, not as `Blob`s, so the code can be tested; the canvas work that
  shrinks them was checked in a real browser instead.
- Building the farm file does not count as saving it. The save time is recorded only once the file has left the
  phone, so a cancelled iPhone share sheet does not silence the reminder.
- On iPhone the file is handed over through the share sheet ("Save to Files"); elsewhere it downloads.
- iPad is recognised by "Macintosh" in its browser identity plus touch, not by the platform field (Chrome's
  phone emulator reports a Mac platform with an Android identity).
- File names use the person's local date.
- Home is rebuilt whenever the farm changes, so clearing the sample there shows the empty farm at once.
- One tree's entries and photos are read through an index, never by loading the whole farm.
- When the phone is full, every write says so plainly, and a record whose second write fails is taken back out.
- The sample farm is generated by a seeded script; its named trees have the species their names say. Loading
  it keeps the person's own name.
- The web app manifest lives in its own module so it can be tested; the test reads files through Vite, because
  the frontend type-checks with browser types only.
- The Supabase migration has a timestamp name, as the Supabase command line expects. Row-level security is on for
  every table with no policies, so only the API's service key gets through, and both views run with the reader's
  rights.
- The seed creates no account: a known owner password would work against any copy put online.

## Review

A fresh reviewer read the whole branch and asked for fixes; all four are in the last commit, each with a test
that failed first: tree ids restarting at 1 after opening a file or loading the sample; "Something went wrong"
instead of "Phone storage is full" on most writes; the welcome screen able to replace a real farm with the
sample; and the seeded owner password (from an automated security check).

Left for later, all small:

- After opening a farm file, the greeting keeps the old name until the profile is saved.
- Photos from another tool's farm file without a `uid` would all show the first photo.
- The file check does not insist on the owner record or a readable save date.
- The zip is built and read whole in memory: fine for tens of photos, worth streaming for hundreds.
- A tree added through the data functions without an action or priority gets none (the form always sends both).
- A farm started without the welcome screen gets the save reminder at once.
- `docs/screenshots/welcome.png` is not shown in the README.
- The Pages build still carries the server client code (size only).
- Zone outlines cannot be drawn in the app, so a real farm's Land Map shows trees without zone shapes.
- Zone labels on the Land Map overlap at phone width.
- An app update can reload the page mid-form; a prompt before updating would be kinder.
- The tree page's fallback cover is a remote stock photo, which does not show offline.

## Still to check on real phones
